# ATM Star Pilot

将外部规划与客户端批量执行结合起来。当前是开发框架，不能把接入成功说成已支持全部模组或能一键获得 ATM 之星。

## 开始与恢复

1. 从对话、MCP 配置、当前项目或 ATM_PILOT_PROJECT / ATM_PILOT_INSTANCE 找到项目和实例，不假定作者机器路径。接入问题读 [maintenance.md](references/maintenance.md)，可用只读脚本 `scripts/inspect_setup.py --project <project> --instance <instance>`。
2. 先读项目 AGENTS.md、最新 PROGRESS.md（若存在）及实例 config/atmpilot/server-rules.json。当前使用者的最新指示优先；分享包不继承原使用者的权限、坐标或进度。
3. 读取 minecraft_job、minecraft_status / minecraft_live、minecraft_inventory，确认常驻队列、死亡恢复、光标和中断投料，再派发动作。菜单编号和槽位只对当前观察有效。
4. 当前使用者已交付全自动控制时继续执行，不因普通输入反复请求交还控制。F8、主动停止和明确停止始终有效；新接收者默认人工输入优先。

## 推进工作

- 以本服同步 JEI、原生机器菜单和实际库存确定配方。整合包参考数据辅助规划，不能覆盖服务端配方。
- 优先打通总进度瓶颈：AE 存储与自动合成、可持续能源、高吞吐模组加工、资源供给和自动回流。比较升级、并行、供电与整条产线吞吐，按整个 ATM10 的协同选择路线。具体陷阱见 [production.md](references/production.md)。
- 用 minecraft_workflow 或命名 JSON 工作流提交已核实的多步动作。需要外部思考期间继续执行时，用 work_queue.py / tools/run_queue.py 常驻衔接；阶段、恢复和旅行规则见 [operations.md](references/operations.md)。
- 执行中只向同 generation 原子追加新阶段，不改已接受阶段，不抢占它的原生 job。加工等待和正确距离挂机也属于生产，不为保持走动而离开。
- accepted、running、管道存在和电脑转运统计都不等于完成。用实际 job、库存、机器产物、AE 收货或真实任务进度确认结果；失败后不能重放已部分完成的投料或订单。
- 用户要求直接推产线时，控制改进随实际生产使用，不另做演示、往返基准或故意受伤／死亡测试。
- 取放整组优先原生快捷移动，精确数量使用有界批量点击并核对同步；合成整组原生 Shift、余量批量收取。已知缺料先补料，不用重放整条已部分完成的合成。
- 采矿可用 `extension:ore_acquire`，传入实测矿物 `block/item/count/targets/maxBlocks`。只在获准天然区域寻路掘进；原生 Ultimine 的每个预览方块均须同矿物、在边界内、无流体和设施，预览变化时释放连锁键。能力已编译不等于实际采得矿物，以库存增量确认。

## 边界

- 共同基地与其他玩家设施保持原状。取料授权不包含机器、管线、电网、AE 样板、升级或过滤修改。只在已完整调查并记录的自有区域施工、采掘和配置，包含自动机器的整个工作范围。
- 区域有 unloaded 或 truncated 时不能把缺失记录当成空气；细分后重读。minecraft_region 最多查询 32768 格、返回 4096 条方块记录。
- 使用正常生存动作，不生成物品、写玩家能力、伪造任务或绕过服务端权限。mayfly=false,flying=true 可能来自合法模组飞行。
- 旅行按当前用户授权，用登记的现成门、传送台或真实权限下的原生地图 TP。travelAccessOnly 点只允许交通，不扩大施工授权。
- 本地反击、挡路清理与有界战斗以当前守则为准，玩家与受保护生物继续受保护。危险超出能力时保留断点撤离，不关闭守护强行推进。
- 当前项目使用者最新授权为受击本地反击、普通执行失败留在现场，只有原生生命值≤1才紧急回家；F8、显式停止继续优先。其他接收者须使用自己的授权，不继承这一阈值。
- 死亡只恢复自己的墓碑；未知结果的 /back 不连续重试。光标非空、人工停止及未确认订单先处理断点。
- 掉落物分流按当前用户约定。采用本项目可堆叠分流时，不可堆叠装备／武器／工具及背包不进 AE，其余可堆叠材料可入库，包括带组件材料与宝石；不要恢复旧空 NBT 白名单。

## 维护与交付

编辑流程、热模块或核心时读 [maintenance.md](references/maintenance.md)。优先将可变能力放热模块；核心热替换受 JVM 类结构限制，不保证任意更新免重启。

用户要求分享时构建匹配的核心与热模块，运行项目打包器，核对归档和安装模板，将本 skill 一起提供；排除会话、个人规则、旧队列、运行证据和其他模组 JAR。不要为了打包启动或重启游戏。

汇报实际完成的产线与剩余瓶颈。只有实际获得对应物品，才宣称 ATM 之星完成。
